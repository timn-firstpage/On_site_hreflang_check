# Onsite Hreflang Audit

Produce `15.1-15.3_{name}_onsite_hreflang_audit_{date}.xlsx` for checks 15.1–15.3, where the prefix is the covered checklist item range, name is the company/site name and date is YYYY-MM-DD. Retain the range when items are N/A, Human check or unverified. Read [audit rules](references/audit-rules.md) and [output contract](references/output-contract.md) before judging evidence. These user-selected first-check rules take precedence over generic SEO recommendations.

## Workflow

1. Obtain site/company, supplied global config and existing crawl/exports. Read [shared configuration](references/shared-config.md). Honor `checks.hreflang=false` by not running this flow. Reuse site-matched evidence and the common handover; do not reload a profile per audit.
2. Preflight a writable unique run directory and Python with openpyxl before expensive retrieval. Resolve paths on the executing host; do not assume another user's runtime or Downloads path. Use the supplied config directory as the base for relative paths.
3. For supplied `.seospider`, follow the shared saved-crawl contract: reuse exports or open once using verified supported SF operations, preserve active/unsaved sessions, and fall back once to manual saved-crawl Open plus exact exports. Never deserialize arbitrary binaries. `allow_new_crawl=false` still allows reading saved evidence. New preparation, when permitted and needed, belongs to `sf-shared-config`; it owns profile selection, sitemap confirmation and manual Start.
4. Use the Python code workflow in [homepage inspection](references/homepage-inspection.md) for 15.1/15.2. No computer-use, native UI or browser-control MCP capability is required or to be invoked. First review site-matched saved HTML/SF evidence and previous homepage-evidence.json. Reuse sufficient evidence via --html or --reuse-evidence; neither makes HTTP requests. Preserve its date and unresolved checks. Only collect missing evidence online. Read discovered hrefs, options, hreflang and target responses before considering optional programmatic Playwright rendering. --render loads the homepage directly, without a preceding static HTTP pass or automatic fallback. Reuse known selectors to avoid a separate discovery run when possible. Classify actual alternate URLs independently of click success. Never ask for desktop control as a prerequisite. JS-only behavior uses the optional code runner if available; missing runtime/blocked resources are evidence limitations, not website defects. A JS library string, HTML lang, or single self-reference alone does not prove multiple versions. Record exactly which URL/content changed and which interaction was tested; avoid vague “could not verify switch” findings.

   Use the shared 2-second minimum request interval (configurable via budget.min_request_interval_seconds). On any HTTP 429, stop further live requests in that run. The helper persists host-scoped cooldown in .hreflang-state beside the config; sequential reruns sharing it make zero requests during cooldown, including --render. Use --state-dir for a shared writable location when config is read-only or other config files cover the same site. Record Retry-After and retry_not_before in the shared manifest; do not immediately rerun or switch clients to escape the limit. Do not overlap SF or other audit runs: the helper does not coordinate their traffic. Retain usable cached/SF evidence. A live homepage 429 is an access limitation, not proof of failed switching; preserve the separate six-filter policy for actual SF findings.
5. Read complete SF Hreflang exports using the six filters in the rules. Retain source Address, target URL, language value and error detail where present. Count distinct source URLs in Missing, preserving query strings: 1–100 → X; more than 100 → Human check pending review for parameter-page inflation or SF crawl errors. Any confirmed issue in the other five filters still makes 15.3 X; keep unreviewed high-volume Missing rows in the archive, not the confirmed issue sheet. Instruction: “请检查是否有大量参数页或 Screaming Frog 抓取异常。” Findings states the actual Missing count and pending review, without claiming a cause. No percentage threshold or automatic recrawl. Do not infer counts from a truncated preview. After evidence-backed review, confirmed defects can be X; resolved false positives can be √.
6. Write reviewed `findings.json` using the output contract. Checklist columns are Item No., Item Name, Check Result, Findings and Instruction; there is no Coverage column. Findings states the observed result and brief limitations. Instruction states the next step a person must take, usually in one short sentence; write “无需处理。” / “No action needed.” when no action is needed. Use √ / X for pass/fail, never Yes/No; retain N/A and Human check when applicable. Missing SF evidence is the explicit 15.3 exception: tick √ with the unverified/missing-result fact in Findings and a short request to supply exports in Instruction only when neither a confirmed X nor the large-Missing Human check applies. Keep full provenance in the evidence archive, not the action column. Other uncertain judgments use Human check.
7. Run `python scripts/build_report.py --input <findings.json> --output-dir <unique-run-directory>`. It validates structure, writes literal text, verifies the saved workbook and refuses overwrite. Inspect worksheet layout, especially long issue text, using an available spreadsheet renderer or viewer. Preserve evidence and findings on failure; rerun only the affected export step after correcting the error.

## Delivery

Always return the three-row Checklist. Create `15. HREFLANG` only when any check is X; include every X's issue details. Report first-check exceptions and actual crawl scope/date. Do not claim an all-pages clean audit when coverage is partial or unavailable. Read [README](README.md) for installation, examples and testing. No site repair, automatic crawling, scheduling, messaging or GitHub publication is included in invocation.
